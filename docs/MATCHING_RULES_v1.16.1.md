# ReceiptHub v1.16.1 明細照合・未使用書類表示ルール

## 1. 照合候補と表示対象を分離する

カード明細には前月末の遅延計上が含まれるため、照合候補は明細行の実利用月すべてから取得する。例えば2026年7月明細に2026年6月28日の取引があれば、2026年6月・7月の領収書を照合候補に含める。

一方、「明細に紐づかなかった提出書類」は、広い照合候補プール全体をそのまま表示してはならない。物理PDFを表示対象にするのは次のいずれかの場合だけとする。

1. PDF本文から抽出した書類日または取引日が、選択中の領収書発行月に属する。
2. 過去月PDFでも、実際の明細行と請求元が一致し、通常決済なら日付±1日、返金なら既定の返金探索期間内にある。
3. 日付を抽出できない解析不足PDFで、選択月に対応する提出サイクルへ保存されている。

保存先の提出月だけでは判定しない。管理者が古い領収書を現在の提出サイクルへ再アップロードしても、PDF本文の日付が古く実明細とも無関係なら当月の未使用一覧へ表示しない。

## 2. 過去月書類の扱い

過去月の領収書は次の用途で引き続き使用できる。

- 前月末取引との直接一致
- 返品・取消行の元決済確認
- 法人カード単位の後日返金相殺
- 契約変更推定の補助証拠
- 明細行に関連するものの構成要素を抽出できない場合の解析要確認

ただし、過去月書類が照合候補として読み込まれただけで、実際の明細行と請求元・日付が関連しない場合は、当月の「明細に紐づかなかった提出書類」へ表示しない。

## 3. 物理PDFと構成要素

Refund PDFに元決済と返金の複数構成要素があっても、未使用一覧では物理PDFを1件として表示する。PDF内のいずれかの構成要素が使用済みなら、そのPDF全体を完全未使用として重複表示しない。

## 4. 2026年7月の期待動作

- 6月28日の藤本さん220 USD領収書は、0383・0466の照合候補として参照できる。
- 6月28日付近でAnthropic明細に関連する過去月書類は、未解決時の確認対象として残せる。
- 5月31日・6月1日など、実明細と日付が離れた無関係な過去月領収書は表示しない。
- PDF本文の日付が7月に属する未使用書類は表示する。
- 画面とPDFの件数は、上記の表示対象となった物理PDF数を示す。
