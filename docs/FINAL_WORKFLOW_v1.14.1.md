# ReceiptHub v1.14.1 最終運用フロー

## 目的

v1.14.1では、当月に提出された領収書だけでは直接一致しないものの、契約・プラン変更書類と過去の旧プラン領収書を合わせると合理的に説明できるカード明細を、管理者確認前の「推定対応」として提示します。

この推定は、未提出を隠すための緩い照合ではありません。通常の直接照合、重複排除、返金照合を先に実行し、それでも未一致の行だけに、明示された契約変更情報と同一ユーザーの過去実績を用います。

## 例

```text
当月の契約変更書類
利用者: ryota.uchiyama@hakuhodo.co.jp
旧プラン: Claude Pro
新プラン: Max plan - 20x
変更日: 2026-06-06
旧プラン終了日: 2026-06-08
当月支払額: 218.01 USD

過去月の領収書
利用者: ryota.uchiyama@hakuhodo.co.jp
プラン: Claude Pro
日付: 2026-05-08
金額: 22.00 USD

未一致カード明細
利用日: 2026-06-08
請求元: Anthropic
金額: 22.00 USD

結果
推定対応（管理者確認待ち）
```

## 推定の必須条件

次をすべて満たす場合だけ推定候補を作ります。

1. 通常の当月照合では未一致である
2. 明細・契約変更書類・過去領収書の請求元グループが同じ
3. 契約変更書類に旧プラン名と旧プラン終了日が明記されている
4. 契約変更情報の信頼度が0.75以上
5. 明細利用日が旧プラン終了日の前後1日以内
6. 契約変更書類と過去領収書が同一ユーザーに属する
7. 過去領収書に旧プラン名が明記されている。旧プラン名を抽出できない場合は、同一ユーザーに登録されたサブスクリプションであること
8. 過去領収書が明細利用日の前月に属する
9. 明細と過去領収書の金額・通貨が完全一致する
10. 過去の請求日と今回明細日の日が前後1日以内
11. 過去領収書の日付は契約変更日より前である
12. 同じ契約変更書類・過去領収書を複数明細へ使用しない
13. 同じ強さで別ユーザー候補が並ぶ場合は推定しない

金額の許容差はありません。利用者を推測する通常照合にも変更しません。利用者情報を使うのは、同一ユーザーの契約変更書類と過去契約実績を結び付ける、この例外的な推定段階だけです。

## 管理者画面

推定対応は橙色で表示します。

```text
明細情報
推定対応
利用者
旧プラン / 新プラン
変更日 / 旧プラン終了日
明細金額
過去領収書の請求日・金額
契約変更書類へのリンク
過去領収書へのリンク
推定理由
```

管理者は次のいずれかを選びます。

### 推定対応を一致として確定

- 明細を一致へ変更
- 判定理由を「契約変更推定を管理者確定」に変更
- 確認管理者・確認日時を保存
- 再照合後も管理者確定結果を維持

### 推定を採用せず未一致

- 明細を未一致へ戻す
- 推定候補を不採用として保存
- 同じ証拠組み合わせを次回再照合で再提示しない
- 新しい契約変更書類または過去領収書が追加された場合は、新しい候補として再評価可能

## AI抽出

領収書AIでは、通常の払先・日付・金額・通貨に加えて次を抽出します。

```text
plan_name
previous_plan
new_plan
change_date
previous_plan_unused_from
previous_plan_end
new_plan_start
new_plan_end
adjustment_amount
adjustment_currency
confidence
```

検索可能なPDFでは埋め込みテキストも使い、`Unused time on ... after ...`や契約期間の記載から安全に補完します。単に複数のプラン名が出ているだけではプラン変更と判定せず、旧プランの未使用期間など明示的な変更表現を必要とします。

## 既存データ

マイグレーション`receipts.0034_plan_change_inference`は推定照合用データを追加し、`receipts.0035_refresh_plan_change_metadata`は既存領収書の契約変更メタデータをPDF埋め込みテキストから再抽出できる状態へ戻し、保存済み明細へ再照合マーカーを付けます。どちらのマイグレーションでもOpenAI APIは実行しません。

デプロイ後、対象月の「ご利用代金明細」を開くか「最新の領収書と再照合」を実行すると、保存済み明細行と領収書を使って新ルールを適用します。過去領収書のプラン名が未抽出でファイルが残っている場合は、埋め込みテキストから補完します。

## v1.14.1のメタデータ再抽出

AIファイル名修正・検査では、`ai_extracted_plan_name`、`plan_change_details`、`plan_change_metadata_checked_at`へ結果を保存します。通常の一括処理はAI確認済み領収書を再検査しませんが、管理者の領収書確認画面から1件だけ明示的に再検査できます。

既存領収書はデータマイグレーション後の次回明細再照合で、OpenAI APIを呼ばずにPDF埋め込みテキストから契約変更メタデータを一度だけ再抽出します。過去領収書から旧プラン名を抽出できない場合でも、同一ユーザーのサブスクリプション、同一請求元、前月、金額・通貨完全一致、請求日周期一致をすべて満たす場合だけ、信頼度を下げた推定対応として管理者確認へ提示します。
