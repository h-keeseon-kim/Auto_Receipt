# ReceiptHub v1.13.0 ご利用代金明細照合ルール

## サービス名と法的販売者

領収書本文にサービス・製品・プラン名が明示される場合は、法的販売者とは別に保持します。明細の請求元グループ判定ではサービス名を優先し、なければ法的販売者を使用します。

```text
Google One請求書
法的販売者: Google Asia Pacific Pte. Ltd.
サービス名: Google One
明細表記: GOOGLE GOOGLE ON
→ GOOGLE_ONEグループとして照合
```

## 明細に紐づかなかった提出書類

一対一照合・重複排除・返金相殺後に使用されなかった提出書類を保存します。表示項目は、ファイル名、利用者、登録項目、本文サービス名、法的販売者、書類日、金額・通貨、最も近い明細、不使用理由です。これにより、カード明細側の誤記、別取引、余剰提出、解析不足を未提出明細とは分けて確認できます。

## 目的

照合の目的は、会社全体のPカード明細について、**各明細行を裏付ける提出書類があるか**を確認することです。誰が利用したかは推定しません。

表示する結果は次の4状態です。

```text
一致       対応する提出書類を確認できた
解析要確認 提出ファイルはあるが、照合に必要な情報を抽出できない
未一致     対応する提出書類を確認できない
対象外     管理者が領収書不要と判断した
```

## v1.12.0を設計した実データ

2026年7月分の全社Pカード明細と、同じ提出サイクルに集まった提出PDFを全件確認しました。

```text
カード明細行                  61件
提出PDF                       63件
明示参照番号による重複除外      2構成要素
一致                          59件
未一致                         2件
```

一致59件の内訳は次のとおりです。

```text
直接一致                       56件
返金書内に記録された元決済       1件
明示的に紐付く返金の相殺          1件
同一請求元内の近接返金相殺        1件
```

この検証から、単純な「1 PDF = 1領収書」では不十分であり、1つのPDF内にある元決済・返金・支払履歴を別々の**取引構成要素**として扱う必要があると判断しました。

## 1. ファイル名を証拠にしない

照合には、アップロード時のファイル名を使いません。ファイル名と本文の金額・サービスが異なる実例があるためです。

使用する情報はPDFまたは画像の本文から抽出します。

```text
書類区分
払先・請求元
決済日・返金日
最終支払額・返金額
通貨
Invoice番号
Receipt番号
Transaction ID
関連Transaction ID
Payment history
```

## 2. 金融書類の区分

提出書類を次の3種類に分類します。

```text
支払済み領収書（charge）
請求書（invoice）
返金書類（refund）
```

この画面の目的は会計上の支払確定ではなく、**カード明細行に対応する提出PDFがあるか**の確認です。そのため、本文から請求元・取引日・金額・通貨を明確に確認できる `Invoice / Amount due` も提出証拠として扱います。`PAID`、`Amount paid`、支払履歴などがある書類は支払済み領収書として分類します。支払済み領収書と同じInvoice番号を持つ請求書が両方提出された場合は同じ取引を2件として数えず、支払済み領収書を優先します。書類区分は管理者の監査情報として保持します。

## 3. 取引構成要素

1つのPDFが複数の金融イベントを証明することがあります。

例：返金書類

```text
元決済  +220.00 USD
返金     -66.48 USD
```

この場合、PDFを1件として扱うのではなく、元決済と返金を別々の構成要素として保存します。1つのPDFが複数構成要素を持つことは許可しますが、同じ構成要素を複数の明細行へ重複使用しません。

## 4. 重複排除

重複排除は、次のような**明示的な識別子が同じ場合だけ**行います。

```text
Invoice番号
Receipt番号
Transaction ID
決済参照番号
```

次の条件だけでは重複扱いにしません。

```text
同じ払先
同じ日付
同じ金額
同じ通貨
```

同じ日に同じサービスの同額決済が複数発生するためです。

重複時の優先順位は次です。

```text
支払済み領収書
返金書類内のPayment historyにある元決済
未支払を含む請求書
```

## 5. 直接一致

通常の支払は、次の条件をすべて満たす場合に一致候補となります。

```text
請求元グループが一致
金額と通貨が完全一致
明細利用日と取引日が±1日以内
```

金額の許容差はありません。

```text
22.00 USD と 22.00 USD  一致可能
22.00 USD と 22.01 USD  不一致
15,400 JPY と 15,401 JPY 不一致
```

外貨明細には外貨金額・通貨を優先し、円建て明細には円金額を使用します。外貨額と円換算額を直接比較しません。

## 6. 全体一対一割当

同じ請求元・金額・通貨の明細と領収書が複数ある場合、行ごとに先着順で割り当てません。

全明細行と全構成要素を対象に、次の優先順位で全体割当します。

```text
1. 一致件数を最大化
2. 合計日付差を最小化
3. 支払済み領収書を優先
4. ファイル・構成要素の安定した順序で決定
```

利用者名は割当条件に含めません。どのユーザーの利用かを特定するのではなく、必要数の提出書類が存在するかを確認します。

自動照合の請求元はPDF本文から抽出した払先だけを使います。登録サービス名、サービスマスターの別名、「その他」メモは払先抽出の代用にはしません。PDF本文から払先を確認できないファイルは「解析要確認」にします。

## 7. 返金を含む照合

直接一致で解決しない明細に対して、次の順で返金を考慮します。

### 7.1 返金書類内の元決済

返金書類のPayment history等に元決済が明記されており、その元決済が明細の金額・通貨・請求元・日付条件を満たす場合、元決済を証拠として使用します。

### 7.2 明示的に紐付く返金相殺

元決済と返金がTransaction IDまたはInvoice番号で明示的に紐付いている場合、次の正味額を照合します。

```text
元決済 + 返金 = 明細額
```

例：

```text
42.90 USD + (-11.44 USD) = 31.46 USD
```

### 7.3 同一請求元内の近接返金相殺

カード会社が、同一請求元の返金を別の決済へ相殺した正味額を掲載する実例がありました。そのため、明示リンクで解決できない場合に限り、次をすべて満たす組合せを確認します。

```text
元決済の請求元・通貨が明細と一致
元決済日が明細利用日±1日以内
返金が同じ請求元・通貨で、明細利用日±1日以内
元決済と最大3件の返金の合計が明細額と完全一致
未使用の構成要素だけを使用
```

これは直接一致・明示リンク照合の後にだけ実行します。金額が完全一致しない組合せは使用しません。

## 8. 解析要確認と未一致を分ける

提出ファイルが存在しても、次の情報を抽出できなければ自動照合できません。

```text
取引日
金額
通貨
払先
```

この場合は「未提出」と断定せず、`解析要確認` として黄色表示します。管理者は領収書AI再検査または手動確認を行います。

対応する提出ファイル自体を確認できない場合だけ、`未一致` として赤色表示します。

同一請求元・金額・通貨の明細数より、重複除外後の決済証拠数が少ない場合は、次のように不足数を表示します。

```text
同一条件の明細20件に対し、決済証拠19件。少なくとも1件不足。
```

## 9. 管理画面・照合結果PDF

明細行には次を表示します。

```text
明細番号・利用日・ご利用先・明細金額
一致 / 解析要確認 / 未一致 / 対象外
対応した提出ファイル
支払・返金の内訳
判定メモ
```

色は次です。

```text
一致       緑系
解析要確認 黄色系
未一致     赤系
対象外     グレー
```

返金相殺の場合は計算内訳も表示します。

```text
137.26 USD - 66.48 USD - 6.78 USD = 64.00 USD
```

## 10. 再照合

新しい領収書が追加された後は「最新の領収書と再照合」を実行します。

```text
明細PDFのOpenAI再解析       しない
保存済み明細行の再利用      する
最新の提出PDF本文解析        する
一対一照合・返金相殺の再実行 する
```

画像のみのPDFなど、本文情報を抽出できない書類は、管理者が「AIでファイル名を修正・検査」を実行して金融情報を抽出した後に再照合します。

## 11. 実データ監査で確認した未一致

全件照合では、明細61行のうち59行に証拠を割り当て、2行が未一致でした。

- 同じ請求元・22 USDの明細20件に対し、明示参照番号で重複を除外した決済証拠が19件だったため、少なくとも1件不足
- 1.10 USDの明細に対し、提出された同請求元の書類本文は11.00 USDであり、完全一致する証拠なし

どの利用者の不足かは断定しません。
