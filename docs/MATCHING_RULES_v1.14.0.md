# ReceiptHub v1.14.0 ご利用代金明細照合ルール

## 基本順序

```text
1. PDF本文から取引構成要素を抽出
2. 明示参照番号で重複排除
3. 金額・通貨完全一致、請求元一致、利用日±1日の直接照合
4. 返金書内の元決済、明示返金相殺、同一請求元の近接返金相殺
5. 未一致行だけ、契約変更情報による推定を評価
6. 推定対応は管理者が確定または不採用を判断
```

通常照合の目的は、明細行に対応する提出証拠があるかを確認することであり、利用者を特定しません。契約変更推定だけは、同一ユーザーの当月変更書類と過去旧プラン領収書を結び付けるため、利用者IDを必須条件にします。

## 契約変更書類

契約変更書類として扱うには、少なくとも次が必要です。

```text
旧プラン名
旧プラン終了日
請求元グループ
利用者
信頼度0.75以上
```

新プラン名・変更日・新プラン期間・日割り調整額は根拠表示と順位付けに使います。旧プラン終了日がなければ推定しません。

## 過去旧プラン領収書

過去領収書として扱うには次が必要です。

```text
同一ユーザー
同一請求元グループ
旧プランと関連する明示プラン名
明細利用日の前月
日付・金額・通貨を抽出済み
契約変更日より前
```

明細と金額・通貨は完全一致が必須です。請求日は今回明細日と±1日以内である必要があります。

## 候補の一意性

候補は次の順で優先します。

```text
旧プラン終了日との日付差が小さい
過去請求日と今回明細日の差が小さい
契約変更情報の信頼度が高い
過去書類の品質が高い
```

同じ順位で異なるユーザーが並ぶ場合は、任意の利用者を選ばず推定しません。

同じ契約変更書類と過去領収書は、それぞれ1件の明細にだけ使用します。複数の未一致明細が同じ証拠を要求する場合、旧プラン終了日と完全一致する行を優先します。

## 結果状態

```text
一致       直接証拠または管理者確定済み
推定対応   契約変更情報から合理的に推定できるが管理者未確認
解析要確認 関連ファイルはあるが照合情報を抽出できない
未一致     対応証拠も有効な推定もない
対象外     管理者が領収書不要と判断
```

推定対応を未一致と同じ赤色にはせず、橙色で表示します。照合結果PDFでも同じ区分を使用します。

## 管理者確定

「推定対応を一致として確定」すると、明細の一致状態と監査履歴を保存し、通常の再照合で上書きしません。

「推定を採用せず未一致」を選ぶと、候補指紋を不採用として保存します。同じ証拠組み合わせは再提示しませんが、別の過去領収書や契約変更書類が追加された場合は新しい候補として評価します。
