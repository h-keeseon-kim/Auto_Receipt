# ReceiptHub v1.16.0 最終ワークフロー

1. 管理者が全社カード明細PDFをアップロードする。
2. OpenAI抽出時、返品・取消行はご利用先末尾に`（返品）`を付ける。
3. 保存された明細行の取引年月を収集し、対応するすべての領収書発行月からPカード対象PDFを取得する。
4. PDF本文から、物理PDFごとに決済・返金の金融構成要素を作る。
5. Invoice番号・Transaction IDが同一の重複証拠を除外する。
6. 通常決済を金額・通貨完全一致、請求元一致または既知互換、日付±1日で全体最適割当する。
7. Refund内の元決済および明示的に紐付く返金相殺を照合する。
8. 残る明細へ、同一法人カード・同一請求元・同一通貨の後日返金をグローバルに割り当てる。
9. 返品・取消行を、同日元決済と正味再計上の決済グループへ接続する。
10. 直接証拠がない場合に限り、既存の契約変更推定を実行する。
11. 未使用一覧を物理PDF単位で作成し、一部使用済みPDFの重複表示を防ぐ。
12. 管理者画面と照合結果PDFへ、計算式・証拠ファイル・判定理由を表示する。
