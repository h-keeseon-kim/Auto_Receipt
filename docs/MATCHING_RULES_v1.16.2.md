# ReceiptHub v1.16.2 全明細共通の証拠使用ルール

## 1. 管理単位はPDFではなく金融イベント構成要素

1つのRefund／Credit Note PDFには、元決済と返金が同時に記載されることがある。そのため、物理PDFを一度使用したかどうかだけでは正確に管理できない。

```text
Refund PDF
├─ 元決済 +22.00 USD
└─ 返金   -4.97 USD
```

ReceiptHubは各構成要素を`CardStatementReceiptEvidence`として保存し、元決済と返金を独立して使用管理する。

## 2. 安定フィンガープリント

`component_key`は1回のAI抽出内でのローカル識別子であり、再アップロードや再解析で変化し得る。全期間の所有権には`component_fingerprint`を使う。

識別情報の優先順位は次のとおり。

1. Invoice番号＋正規化販売者＋役割＋金額＋通貨
2. Transaction ID＋正規化販売者＋役割＋金額＋通貨
3. 関連Transaction ID＋返金日等の金融署名
4. PDF SHA-256＋正規化販売者＋役割＋金額＋通貨＋取引日
5. ファイルを取得できない旧データだけ、Receipt IDを含む保守的なレガシー識別

元のReceiptと、後日Refund PDFのPayment historyに記載された元決済が同じInvoice番号を持つ場合、同じ構成要素として扱う。

PDF SHA-256を使う場合、AIが付けた`primary`、`payment-history`等の構成要素名はフィンガープリントへ含めない。再解析で名称が変わっても、同じPDF・同じ金融署名なら同じ取引としてロックする。同一PDF内に金融参照番号のない完全同一署名が複数ある場合は、二重使用を避けるため同一証拠として保守的に重複排除する。

## 3. consumeとreference

### consume

金額計算へ加算・減算した構成要素。

```text
A = あ + い + う
```

この場合、あ・い・うはすべて`consume`としてAの証拠使用履歴に保存される。DB制約`uniq_consumed_component_fp`により、同じフィンガープリントを別明細へ`consume`登録できない。

### reference

返品・取消行が元決済を確認するなど、関係の証明には使用するが金額を消費しない構成要素。

```text
0383 返品行       → 藤本220 USDをreference
0466 正味再計上行 → 藤本220 USDをconsume
```

`reference`は複数明細から参照でき、将来の正当な`consume`を妨げない。

## 4. 明細間の所有権

### 管理者確定

管理者確定は常に自動照合より優先する。自動処理は管理者確定行の証拠を削除・移動しない。

複数の管理者確定が同じ構成要素を使用している旧データがある場合は、一方を自動で破棄せず競合メモを残して確認対象にする。

### 自動照合

自動割当同士では次の順で早い明細を所有者とする。

1. 明細月
2. 明細アップロード日時
3. CardStatement ID
4. 明細行順・ID

より前の明細が、後続明細ですでに使用されている構成要素を必要とする場合、後続明細の証拠1件だけを外すのではなく、その金額計算グループ全体を解放する。

```text
後続B = 元決済 + 返金1 + 返金2
```

返金1の所有権を先行Aへ戻す必要があれば、Bの3構成要素をまとめて解放し、Bを未一致・再照合待ちへ戻す。部分的な壊れた計算を残さない。

## 5. 同じ明細の再照合

再照合開始時に、その明細が持つ旧**自動**`consume`／`reference`行だけをトランザクション内で削除する。管理者確定行は維持する。

再計算に失敗した場合はトランザクション全体がロールバックされるため、旧割当だけが失われることはない。

DBの条件付き一意制約で並行実行時の二重取得を防ぎ、競合時は1回だけ再試行する。

## 6. 全明細で未消費の提出書類

画面・PDFの一覧には、選択中の明細で未使用というだけではなく、**全カード明細を通じて未消費の構成要素が残る物理PDF**だけを表示する。

### 全期間未使用

PDF内の全構成要素が`consume`されていない。

### 一部使用済み

元決済・返金等の一部は他の明細で`consume`済みだが、少なくとも1構成要素が未消費。

```text
元決済 +22.00 USD → 2026-06明細 0384で使用済み
返金    -0.64 USD → 未使用
```

PDFを表示し、構成要素ごとに使用先明細月・明細No.・`consume/reference`を示す。

### 参照済み・未消費

`reference`のみで使われた構成要素は、金額計算にはまだ利用可能なため一覧に残す。

### 非表示

- PDF内の全構成要素が`consume`済み
- 同じ金融イベントの重複PDF
- 月跨ぎ候補として内部参照しただけで、対象明細と無関係な過去月PDF

## 7. 再計算を起動する変更

次の変更で、影響する明細の`reconciled_at`と未消費スナップショットを無効化し、時系列順に再照合する。

- 領収書の追加・差し替え・AI解析更新
- 領収書の削除・保存期限処理
- カード明細の削除
- 管理者による明細行の確定・対象外・照合対象復帰
- 先行明細による後続自動割当の奪回

複数明細が互いのスナップショットを無効化するため、最大4ラウンドの固定点処理で所有権が収束するまで時系列再照合する。

## 8. 既存データ移行

`0041_global_component_usage_ledger`でフィールド・索引・一意制約を追加する。

`0042_global_component_usage_consistency`で現行正規化方式に基づき既存証拠のフィンガープリントを再構築し、重複した旧自動割当は計算グループ単位で解放する。全明細を再照合待ちにするが、保存済み明細行を使用するためカード明細PDFのAI再解析は行わない。
