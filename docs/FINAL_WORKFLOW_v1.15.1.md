# ReceiptHub v1.15.1 最終フロー

## 1. 月表示

管理者の提出履歴では、内部提出サイクルではなく領収書発行月を選択する。初期値は現在月の前月。例として2026年8月に開く場合は2026年7月を表示し、内部では2026年8月提出サイクルを参照する。

## 2. 提出履歴

上部集計は次の2項目だけを表示する。

- AI未確認
- 未提出ユーザー（API利用確認待ちを含む）

提出状況一覧では、ユーザー、利用状態、提出状態、API確認待ち、操作を表示する。

アップロード済み領収書の絞り込みは次の4区分に限定する。

- すべて
- 再提出判断待ち
- 確認が必要
- AI未確認

サービス／ファイル欄ではアップロード元のラベルを表示せず、操作した実行者だけを表示する。

## 3. 契約変更による推定対応

通常の当月領収書照合で未一致になった明細だけを対象にする。契約変更書類から次の情報を取得する。

- Bill toメールアドレス
- 旧プラン
- 新プラン
- 変更日
- 旧プラン終了日

Bill toメールが一般ユーザーへ一意に一致し、前月カード明細に同一請求元、金額・通貨完全一致、請求日±1日の実績がある場合、当月未一致明細を`推定対応`にする。前月カード明細は領収書提出証拠ではなく、旧プランの金額・請求周期を裏付ける補助証拠である。

同一の契約変更書類と前月明細実績は、それぞれ1明細にだけ割り当てる。管理者は推定根拠を確認し、次のいずれかを選ぶ。

- 推定対応を一致として確定
- 推定を採用せず未一致

## 4. ご利用代金明細

結果集計は次の4項目だけを表示する。

- 明細行
- 解析要確認
- 未一致（推定対応を含む）
- 明細未使用の提出書類

絞り込みボタンは次の2つだけを表示する。

- 未一致
- 解析要確認

未一致絞り込みには、推定対応、直接未一致、明細に紐づかなかった提出書類を含める。画面内では3区分を別セクションとして表示し、推定対応は橙色、直接未一致は赤色で区別する。
