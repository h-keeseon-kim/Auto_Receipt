# ReceiptHub v1.11.0 最終運用フロー

## ご利用代金明細照合の目的

ご利用代金明細照合では、カード明細の各行について、対応する領収書が提出されているかだけを確認します。

```text
必要な結果
├ 一致：対応する提出済み領収書がある
├ 未一致：対応する提出済み領収書がない
└ 対象外：管理者が領収書不要と判断した
```

誰が利用した請求なのかは推定しません。管理画面・照合結果PDFにも利用者候補やサービス所有者候補を表示しません。

## 照合条件

明細行と領収書は、次の3条件をすべて満たす場合だけ一致とします。

1. 金額と通貨が完全一致
2. 明細利用日と領収書日付の差が±1日以内
3. 明細のご利用先と領収書の実際の払先が関連

### 金額・通貨

```text
22.00 USD と 22.00 USD  → 一致可能
22.00 USD と 22.000 USD → 数値が同じため一致可能
22.00 USD と 22.01 USD  → 不一致
15,400 JPY と 15,401 JPY → 不一致
通貨不明・金額不明       → 不一致
```

許容差はありません。

### 日付

```text
明細 6月10日 / 領収書 6月9日  → 一致可能
明細 6月10日 / 領収書 6月10日 → 一致可能
明細 6月10日 / 領収書 6月11日 → 一致可能
明細 6月10日 / 領収書 6月12日 → 不一致
```

### ご利用先・払先

法人格、ドメイン、請求表記の差は正規化して比較します。

```text
CLAUDE.AI SUBSCR / ANTHROPIC.COM
↔ Anthropic, PBC

OPENAI *CHATGPT / OPENAI.COM
↔ OpenAI, LLC
```

`AI`、`API`、`BILLING`などの一般語だけが共通している場合は関連ありにしません。

## 複数の似た領収書

同じ金額・払先で日付も近い領収書が複数ある場合、どのユーザーの領収書かは判断しません。未使用の領収書から次の順で1件を割り当てます。

```text
1. 日付差が小さい
2. アップロード日時が早い
3. 領収書IDが小さい
```

1件の領収書を複数の明細行へ重複して使用しません。必要な領収書数が明細行数より少ない場合、割り当てられなかった明細行は未一致になります。

## 管理者画面

各明細行をカード形式で表示します。

```text
明細番号・利用日・ご利用先・金額
照合状態
対応領収書
判定メモ
管理者操作
```

照合候補一覧、候補スコア、優先順位、曖昧候補、候補からの手動確定は表示しません。

### 色

- 一致：通常または緑系
- 未一致：赤色
- 対象外：グレー

未一致は、3条件をすべて満たす未使用の提出済み領収書がないことを意味します。

### 管理者操作

```text
領収書対象外にする
領収書対象に戻す
最新の領収書と再照合
```

新しい領収書のアップロード後に「最新の領収書と再照合」を実行すると、保存済み明細行と領収書だけを再照合します。明細PDFをOpenAIへ再送信しません。

## 照合結果PDF

PDFには次を掲載します。

- 明細月と対象領収書月
- 明細書基本情報
- 未一致行一覧
- 全明細照合結果
- 対応領収書ファイル名

利用者名・ユーザー候補・サービス候補は掲載しません。未一致行は赤色でハイライトします。

## API利用なし申告

利用者を推定して申告を取り消しません。明細行へ実際に領収書が一致し、その領収書が登録サービスに紐づいている場合だけ、該当ユーザーの「対象領収書月は利用なし」申告を取り消します。

## 既存データ移行

マイグレーション：

```text
receipts.0031_simple_statement_receipt_matching
```

実施内容：

- 旧照合候補テーブルを削除
- 旧「曖昧」行を未一致へ戻す
- 既存解析済み明細へ再照合マーカーを追加
- 次回の明細ページ表示時に保存済み行と領収書を新ルールで再照合
- 明細PDFのOpenAI再解析は行わない
